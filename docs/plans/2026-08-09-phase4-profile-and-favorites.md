# Phase 4: プロフィールとお気に入り

**目的**: ログインユーザー向けのプロフィールページを用意し、別名、お気に入り、ネタバレ防止ボタンを実装する。

**依存**: Phase 2。お気に入りとネタバレ防止ボタンはシナリオを参照するため、その部分だけ Phase 1 を待つ。Phase 3 とは並行して進められる。

**設計**: [ADR-0001](../adr/0001-application-architecture.md)

## データモデル

- `PersonAlias`: `person_id`、`name`、`context`（どの Discord サーバでの名前かの補足）。1 人が複数持つ
- `Favorite`: `person_id`、`scenario_id`
- `SpoilerReveal`: `person_id`、`scenario_id`。ネタバレ防止ボタンを押した記録

Person の表示名、アイコン、X のアカウント名は Phase 2 で作った `people` に既にある。

## 編集できる範囲

| 対象 | 本人 | 管理者 | それ以外 |
| --- | --- | --- | --- |
| 表示名、アイコン、別名、X のアカウント名 | 変更できる | 変更できる | 閲覧のみ |
| お気に入り | 変更できる | 変更できる | 閲覧のみ |
| グループ所属 | 変更できない | 変更できる | 閲覧のみ |

プロフィールページ自体がログイン必須エリアであり、Person 未紐づけのユーザーは閲覧できない。

## 作成するファイル

- マイグレーション: `person_aliases`、`favorites`、`spoiler_reveals`
- モデル: `PersonAlias`、`Favorite`、`SpoilerReveal`
- `app/policies/person_policy.rb`
- `app/controllers/people_controller.rb`: 一覧、詳細、編集、更新
- `app/controllers/favorites_controller.rb`
- `app/controllers/spoiler_reveals_controller.rb`
- `app/views/people/` 配下のテンプレート
- `app/views/scenarios/_preparation_note.html.erb`: Phase 1 が空で置いた部分テンプレートを埋める。`show.html.erb` 自体には触らない
- spec: モデルスペック、`spec/policies/person_policy_spec.rb`、リクエストスペック、システムスペック 1 本

## 作業順序

1. `PersonAlias` のモデルスペックを書き、失敗を確認してから実装する
2. `PersonPolicy` のスペックを書く。本人、管理者、それ以外、Person 未紐づけ、未ログインの 5 通りを固定する
3. プロフィールの詳細と編集のリクエストスペックを書いてから実装する
4. アイコンを Active Storage で添付する
5. 別名の追加と削除を、プロフィール編集画面の中で行えるようにする
6. `Favorite` のモデルと、お気に入りの追加と解除。Turbo でボタンだけを差し替える
7. プロフィールにお気に入りシナリオの一覧を出す
8. `SpoilerReveal` のモデル。シナリオ詳細の準備情報を、押していない状態では出さないことをリクエストスペックで固定する
9. ネタバレ防止ボタンを実装する。押すと `SpoilerReveal` を作り、Turbo で準備情報の領域だけを差し替える
10. 別の端末でログインしても、押した状態が引き継がれることをリクエストスペックで確認する

## 検証手順

- `bin/rspec` がすべて成功する
- 本人がプロフィールを編集でき、他人のプロフィールは編集できない
- 管理者は他人のプロフィールを編集できるが、本人はグループ所属を変更できない
- 別名を複数登録し、プロフィールに並ぶ
- お気に入りの追加と解除がページ全体を再読み込みせずに反映される
- ネタバレ防止ボタンを押す前は、HTML のソースにも準備情報が含まれない
- 押した後にログアウトし、別のブラウザでログインしても準備情報が開いている
- Person 未紐づけのユーザーがプロフィールにアクセスすると弾かれる

## 詰まりそうな箇所

**準備情報を隠す方法**。
CSS で隠すだけでは、ソースを見れば読めてしまう。
サーバ側で `SpoilerReveal` の有無を見て、なければ本文をレスポンスに含めない。

**お気に入りとネタバレの主体**。
どちらも Person に紐づく。
Person 未紐づけのユーザーはボタンを押せない。
このとき例外にせず、ボタン自体を出さない形にする。

**管理者による代理編集**。
管理者が他人のプロフィールを編集できるため、編集フォームの対象が `current_person` とは限らない。
フォームの対象を URL のパラメータから引き、その都度 Pundit で確認する。

**グループ所属の編集場所**。
本人は変更できないため、プロフィールの編集フォームには置かない。
管理者だけが使う Person の編集画面で扱う。

**別名の用途**。
別名は Discord のサーバごとに名前が違う場合の対応付けであり、表示名の代わりではない。
セッションの参加者表示には Person の表示名を使う。
